## User Input

```text
$ARGUMENTS
```

You **MUST** consider the user input before proceeding (if not empty).

## Overview

Creates a git branch following We Are Home conventions, commits changes,
pushes, and opens a Pull Request with the correct target branch.

When called **without arguments**, automatically derives the branch type,
description, and commit message from the active feature specification.

**Branch conventions** (from constitution v1.1.0):

| Type | Pattern | PR Target |
|------|---------|-----------|
| `feature` | `feature/<description>` | Current `release/X.Y.Z` |
| `fix` | `fix/<description>` | Current `release/X.Y.Z` |
| `hotfix` | `hotfix/<description>` | `main` |

## Execution Steps

### 1. Resolve Parameters (Manual or Auto)

**Manual mode** (user provides arguments):
From `$ARGUMENTS`, extract:
- **Type**: `feature`, `fix`, or `hotfix` (first word)
- **Description**: kebab-case slug (second word)
- **Commit message**: remainder, or generated from description (optional)

**Auto mode** (no arguments, or only a type with no description):
1. Run the helper to read the active spec:

```bash
bash .specify/scripts/bash/branch-workflow.sh --auto-from-spec [type]
```

This script reads `.specify/feature.json` to find the active feature directory,
then extracts from `spec.md`:
- **Feature title** → generates kebab-case `DESCRIPTION` slug
- **User stories summary** → generates `COMMIT_MSG`
- **Feature branch name** from spec metadata → validates against type
- Outputs: `TYPE=<feature|fix>`, `DESCRIPTION=<slug>`, `COMMIT_MSG=<message>`

2. Present the derived values to the user for confirmation:
   ```
   Auto-derived from spec:
     Type: feature
     Branch: feature/intelligent-presence-simulator
     Commit: feat: add intelligent presence simulator integration
   Proceed? (yes/edit/cancel)
   ```

3. If user says "yes", proceed with derived values. If "edit", let them
   modify any field. If "cancel", exit.

If the spec cannot be found or parsed, fall back to asking the user for
manual input.

### 2. Determine Target Branch

Run the helper script:

```bash
bash .specify/scripts/bash/branch-workflow.sh --determine-target <type>
```

This script:
- For `feature`/`fix`: finds the latest `release/X.Y.Z` branch via `git branch -r`
- For `hotfix`: returns `main`
- Validates that the target branch exists on remote
- Outputs: `TARGET=<branch>` and `RELEASE=<version>`

If no release branch exists, output an error instructing the user to create
`release/0.1.0` first.

### 3. Create Branch

```bash
bash .specify/scripts/bash/branch-workflow.sh --create <type> <description>
```

This script:
- Derives the branch name: `<type>/<description>`
- Checks for local or remote conflicts
- Runs `git checkout -b <branch-name>`
- Confirms creation

### 4. Stage and Commit

Detect what to commit:
- If the working tree is clean, ask the user what to commit (or skip commit)
- If dirty, run `git add -A` and `git commit -m "<message>"`

If the user provided a commit message in $ARGUMENTS, use it. Otherwise
generate one from the branch description.

### 5. Push and Create PR

```bash
bash .specify/scripts/bash/branch-workflow.sh --push-pr <branch> <target> <title> [description]
```

This script:
- Pushes the branch: `git push -u origin <branch>`
- Creates a PR via `gh pr create`:
  - `--base <target>` (release branch for feature/fix, main for hotfix)
  - `--title "<formatted title>"`
  - `--body "<auto-generated body with checklist>"`
- Outputs the PR URL

### 6. Report

Output:
- Branch created: `<branch>`
- PR URL: `<url>`
- Target: `<target>`
- Suggested next step: e.g., "PR will trigger HACS + Hassfest CI validation"

## Pre-Execution Checks

**Check for extension hooks**:
- Check if `.specify/extensions.yml` exists in the project root
- If it exists, look for entries under `hooks.before_branch`
- Execute any enabled mandatory hooks
- Report optional hooks

## Error Handling

| Scenario | Action |
|---|---|
| No `gh` CLI | Instruct: `! curl -sL https://github.com/cli/cli/releases/download/v2.67.0/gh_2.67.0_linux_amd64.tar.gz \| tar xz -C ~/.local/bin` |
| `gh` not authenticated | Instruct: `! gh auth login` |
| No release branch exists | Instruct: create `release/0.1.0` from current `main` |
| Branch name conflict | Ask user for alternative description |
| Working tree clean with no message | Ask user what to commit |
| Push fails (no permission) | Report error with remote URL and suggest checking repo permissions |

## Post-Execution Hooks

Check `.specify/extensions.yml` for `hooks.after_branch` entries and execute
according to standard speckit hook rules (mandatory vs optional).
